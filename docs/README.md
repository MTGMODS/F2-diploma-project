### Зведення NFR

Наведені значення є критеріями приймання, а не результатами вимірювань. Тестовий профіль — Linux, 4 vCPU, 8 GiB RAM, SSD; генератор навантаження працює окремо. Повні умови та способи перевірки наведено в таблиці 1.2 Розділу 1.

| NFR | Технічне обмеження |
| --- | --- |
| 01 | Прогрітий кеш статистики: 50 RPS × 600 с, p95 ≤300 мс, помилки ≤1%, 0 незапущених запитів |
| 02 | Внутрішні операції API: 50 RPS × 600 с, p95 ≤500 мс, помилки ≤1%; зовнішній OAuth і генерація виключені |
| 03 | Отримання VIP-посилання: p95 ≤30 с на 20 послідовних збірках; очікування broker reply ≤30 с |
| 04 | Кеш: fresh 300 с, граничне збереження 86400 с; 1 refresh на набір при 20 конкурентних запитах |
| 05 | TLS ≥1.2, підписаний JWT; 0 успішних доступів до чужих ресурсів у 100 негативних перевірках |
| 06 | 0 ключів, соціальних ID і HWID у 100 відповідях публічної статистики |
| 07 | 0 подвійних активацій одного ключа на різних власників у 20 конкурентних спробах; тарифні квоти пристроїв |
| 08 | Контрольовані відмови залежностей; 0 VIP-посилань для забороненої ліцензії та 0 безмежних очікувань |
| 09 | Sweep 3600 с для покинутих файлів віком >3600 с; шаблони зберігаються |
| 10 | Compose, backup 3 PostgreSQL-БД щонайменше раз на 24 год; цільові RPO ≤24 год, RTO ≤4 год із перевіркою restore |

Етап 1 календаря має статус Done, етапи 2 і 3 — In Progress: аналітичний розділ і вимоги очікують остаточного рев’ю. Формування вимог розпочато достроково; планові дати не змінено. Це не статус програмної реалізації. Для ЛР №4 використовується гілка `feature/chapter1-final` та окремий PR у `main`, без злиття до рев’ю викладача. AI Disclosure ведеться у PKM Workspace.
