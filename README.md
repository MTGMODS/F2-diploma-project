# F2 Diploma Project

Робочий репозиторій кваліфікаційного проєкту бакалавра зі спеціальності F2
«Інженерія програмного забезпечення» (попередній шифр 121), Чернівецький
національний університет імені Юрія Федьковича.

Поточний навчальний етап — лабораторна робота №7 з дисципліни «Технічне
документування та презентація програмних рішень». Репозиторій містить
матеріали аналізу, планування та проєктування нової платформи, які надалі доповнюватимуться описом реалізації та результатами перевірки.
Предмет роботи — **micro-SaaS-платформа** для інфраструктурного супроводу раніше створеного зовнішнього цифрового продукту, а не розроблення самого продукту. Прикладом інтеграції є
наявний програмний помічник для гравців SA-MP.

У проєктному сценарії власник уже готового продукту замовляє окрему платформу для його представлення, розповсюдження та керування доступом. Попередня монолітна система використовується як джерело вимог: з неї визначаються функції та правила, які потрібно зберегти, зокрема формат ліцензійних ключів і прив’язування Telegram, Discord або обох облікових записів. Предмет роботи — **micro-SaaS-платформа**, а не розроблення самого ігрового помічника. Micro-SaaS описує вузькоспеціалізований сервіс, а мікросервісна архітектура — спосіб побудови платформи.

Відповідно до ЛР №2 його версіонована Markdown-копія міститься в
[навігаційному документі](docs/README.md).

AI Disclosure і приватний відгук керівника призначені для особистого PKM
Workspace; вони не публікуються в цьому репозиторії.

Наукова керівниця підтвердила актуальність і практичну спрямованість теми та
рекомендувала зосередитися на обґрунтуванні архітектури, ліцензуванні,
підписках, пристроях і зовнішніх інтеграціях. Цей відгук збережено в приватному
PKM Workspace; формулювання теми й обсяг роботи залишаються попередніми.
Університетські методичні вказівки та завдання лабораторної визначають академічні вимоги до матеріалів проєкту.

## Контроль якості документації

[Docs Quality Gate](https://github.com/MTGMODS/F2-diploma-project/actions/workflows/docs-linter.yml) запускає markdownlint-cli2 для всіх Markdown-файлів у `docs/` при кожному Pull Request у `main`. Конфігурація зберігає перевірки ієрархії заголовків, списків, таблиць і блоків коду; довгі інженерні рядки дозволені. HTML обмежено якорями та перенесеннями рядків. Для двомовного proposal окремо дозволено два заголовки першого рівня. Приватний локальний AI-журнал ігнорується й не публікується в Git.
