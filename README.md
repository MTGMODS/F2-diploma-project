# F2 Diploma Project

Робочий репозиторій кваліфікаційного проєкту бакалавра зі спеціальності F2
«Інженерія програмного забезпечення» (попередній шифр 121), Чернівецький
національний університет імені Юрія Федьковича.

Поточний навчальний етап — лабораторна робота №1 з дисципліни «Технічне
документування та презентація програмних рішень». Репозиторій містить
документацію проєкту; production-код ведеться окремо в
[license-management-platform](https://github.com/MTGMODS/license-management-platform).
Предмет роботи — **micro-SaaS-платформа** для інфраструктурного супроводу раніше створеного зовнішнього цифрового продукту, а не розроблення самого продукту. Прикладом інтеграції є
наявний програмний помічник для гравців SA-MP.

У проєктному сценарії власник уже готового продукту замовляє окрему платформу для його представлення, розповсюдження та керування доступом. Попередня монолітна система використовується як джерело вимог: її початковий стан зафіксовано у новому репозиторії як `v0.0.0`, щоб визначити функції та правила, які потрібно врахувати в новій платформі. Предмет роботи — **micro-SaaS-платформа**, а не розроблення самого ігрового помічника. Micro-SaaS описує вузькоспеціалізований сервіс, а мікросервісна архітектура — спосіб побудови платформи.

## Структура

- `docs/proposal.md` — попередня технічна пропозиція українською та англійською.
- `src/` — місце для версіонованих матеріалів кваліфікаційного проєкту.

Календарний план із чотирма графами ведеться в
[Google Таблицях](https://docs.google.com/spreadsheets/d/1tvdSm1bp8TJ0UajHGIIUUWSU50ErM9CPFZtlZL6_GVQ/edit?usp=sharing)
та доступний із PKM-дошки Trello; копія XLSX не зберігається в Git.

AI Disclosure і приватний відгук керівника призначені для особистого PKM
Workspace; вони не публікуються в цьому репозиторії.

Наукова керівниця підтвердила актуальність і практичну спрямованість теми та
рекомендувала зосередитися на обґрунтуванні архітектури, ліцензуванні,
підписках, пристроях і зовнішніх інтеграціях. Цей відгук збережено в приватному
PKM Workspace; формулювання теми й обсяг роботи залишаються попередніми.
Робочі факти про production-систему звіряються з її кодом; університетські
методичні вказівки та завдання лабораторної визначають академічні вимоги.
